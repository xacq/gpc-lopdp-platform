# Manual para evidencias e identidad

Este manual explica como revisar evidencias, documentos adjuntos y verificaciones de identidad dentro de un expediente.

Aplica para las cuatro instancias:

- VINESA: `https://privacidad.vinesa.com.ec/accounts/login/`
- VINLITORAL: `https://privacidad.vinlitoral.com.ec/accounts/login/`
- PLUSBRAND: `https://privacidad.plusbrand.com.ec/accounts/login/`
- SERVMULTIMARC: `https://privacidad.laguarda.com.ec/accounts/login/`

Cada empresa tiene sus propios expedientes y evidencias. La informacion de una instancia no se comparte automaticamente con las demas.

## 1. Objetivo de la seccion

La seccion **Evidencias** permite revisar:

- verificaciones de identidad del titular;
- documentos adjuntos al expediente;
- archivos de respaldo;
- resultado del escaneo de seguridad de archivos;
- trazabilidad de quien registro una verificacion.

Esta seccion ayuda a confirmar que la solicitud corresponde al titular o a un representante autorizado antes de avanzar con la gestion del derecho.

## 2. Ingreso a evidencias

1. Ingresar al sistema de la empresa correspondiente.
2. Abrir la seccion de expedientes o solicitudes.
3. Entrar al detalle del expediente.
4. En **Canales relacionados**, seleccionar **Evidencias**.

Tambien se puede acceder desde la pestana **Evidencias** dentro del detalle del expediente.

## 3. Estructura de la pantalla

La pantalla muestra dos bloques principales:

1. **Identidad / Historial de verificaciones**.
2. **Archivos / Documentos adjuntos**.

Si el usuario tiene permisos suficientes, tambien aparece la opcion **+ Registrar verificacion de identidad**.

## 4. Registrar una verificacion de identidad

Usar esta opcion cuando se reviso la identidad del titular o representante y se necesita dejar constancia en el expediente.

1. Entrar al expediente.
2. Abrir **Evidencias**.
3. Seleccionar **+ Registrar verificacion de identidad**.
4. Completar:
   - **Metodo**.
   - **Resultado**.
   - **Notas de validacion**.
5. Seleccionar **Guardar verificacion**.

Las notas deben ser claras, breves y suficientes para justificar el resultado.

## 5. Metodos de verificacion disponibles

El sistema permite registrar los siguientes metodos:

| Metodo | Uso recomendado |
| --- | --- |
| Validacion estructural de documento | Cuando se valida formato o consistencia basica del documento. |
| Codigo por correo | Cuando se confirma identidad mediante codigo enviado al correo registrado. |
| Revision documental | Cuando se revisa cedula, RUC, nombramiento, poder u otro documento. |
| Presencial | Cuando la identidad se valida de forma presencial. |
| Manual | Cuando la validacion se realiza por revision interna no automatizada. |
| Otro | Cuando el metodo usado no corresponde a las opciones anteriores. |

## 6. Resultados de verificacion

Los resultados disponibles son:

| Resultado | Significado |
| --- | --- |
| Pendiente | La verificacion aun no esta concluida. |
| Verificado | La identidad fue validada satisfactoriamente. |
| Rechazado | La identidad no pudo validarse o la informacion no corresponde. |
| No concluyente | La informacion revisada no permite confirmar ni rechazar la identidad. |

Recomendacion: cuando el resultado sea **Rechazado** o **No concluyente**, registrar en notas la razon principal.

## 7. Historial de verificaciones

El historial muestra:

- fecha;
- metodo;
- resultado;
- usuario que registro la verificacion;
- notas de validacion.

Las notas pueden estar protegidas segun el perfil del usuario. Si el usuario no tiene permiso para ver datos sensibles, el sistema mostrara **Contenido protegido**.

## 8. Documentos adjuntos

El bloque **Documentos adjuntos** muestra los archivos asociados al expediente.

La tabla incluye:

- fecha de carga;
- tipo de documento;
- nombre del archivo;
- formato;
- estado del escaneo;
- opcion de descarga, si el usuario tiene permiso.

La pantalla interna permite revisar y descargar archivos permitidos. La carga de archivos se realiza por los flujos habilitados del expediente o por el formulario publico cuando aplica.

## 9. Tipos de archivo

Los tipos de adjunto manejados por el sistema son:

| Tipo | Uso |
| --- | --- |
| Documento de identidad | Cedula, pasaporte u otro documento del titular. |
| Documento de representacion | Poder, autorizacion, nombramiento u otro soporte del representante. |
| Documento de respaldo | Soportes adicionales de la solicitud. |
| Documento de solicitud | Documento principal asociado a la solicitud. |
| Documento de respuesta | Archivo de respuesta generado o vinculado al expediente. |
| Exportacion de portabilidad | Archivo generado para solicitudes de portabilidad, si aplica. |
| Otro | Archivo que no corresponde a los tipos anteriores. |

## 10. Visibilidad de archivos

Los archivos pueden tener dos niveles de visibilidad:

| Visibilidad | Significado |
| --- | --- |
| Interno | Solo para gestion interna autorizada. |
| Visible al titular | Puede estar disponible para el titular, segun el flujo del sistema. |

Antes de hacer visible un documento al titular, se debe revisar que no contenga informacion interna o datos personales de terceros.

## 11. Escaneo de seguridad

Cada archivo puede tener un estado de escaneo:

| Estado | Significado |
| --- | --- |
| Pendiente | El archivo aun no ha sido escaneado. |
| Limpio | No se detectaron amenazas. |
| Infectado | Se detecto una posible amenaza. |
| Fallido | No fue posible completar el escaneo. |
| No aplica | El escaneo no aplica para ese archivo o flujo. |

No se recomienda descargar ni usar archivos con estado **Infectado** o **Fallido** sin validacion tecnica previa.

## 12. Descarga de archivos

Para descargar un archivo:

1. Entrar al expediente.
2. Abrir **Evidencias**.
3. Ubicar el archivo en **Documentos adjuntos**.
4. Seleccionar **Descargar**.

Si no aparece la opcion **Descargar**, puede deberse a permisos del usuario o a proteccion de datos sensibles.

## 13. Buenas practicas para verificacion

- Revisar que los datos del documento coincidan con la solicitud.
- Confirmar si la solicitud la realiza el titular o un representante.
- Si existe representante, revisar el documento de representacion.
- No aprobar identidad si hay dudas razonables.
- Registrar notas claras cuando la verificacion sea rechazada o no concluyente.
- No incluir informacion excesiva o innecesaria en las notas.

## 14. Buenas practicas para documentos

- Descargar archivos solo cuando sea necesario.
- No reenviar documentos personales por canales no autorizados.
- No guardar copias locales fuera de los repositorios definidos por la empresa.
- Revisar el estado de escaneo antes de abrir archivos.
- Mantener la trazabilidad dentro del expediente.

## 15. Problemas frecuentes

### No puedo registrar verificacion

Puede deberse a permisos insuficientes o a que el expediente no esta disponible para gestion del usuario.

### Veo "Contenido protegido"

El usuario no tiene permiso para ver notas o datos sensibles de esa verificacion.

### No aparece el boton Descargar

Puede deberse a falta de permisos para descargar documentos sensibles.

### El archivo aparece como Infectado o Fallido

No abrir ni reenviar el archivo. Reportar el caso al responsable tecnico o administrador del sistema.

## 16. Recomendacion final

La seccion de evidencias debe usarse como respaldo formal del expediente. Toda decision sobre identidad o representacion debe quedar sustentada con un resultado de verificacion y, cuando sea necesario, una nota breve que explique el criterio aplicado.
